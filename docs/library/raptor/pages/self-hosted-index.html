Self-Hosted Deployment

Deploy Raptor on your own infrastructure with Docker Compose or a standalone binary.

Self-Hosted Deployment

Raptor ships as a single Go binary (control-panel) backed by PostgreSQL 16+. The Docker Compose bundle is the fastest path to a running instance. For production, you can run the binary directly, use the provided container images, or deploy behind your own orchestration layer.

Prerequisites

| Requirement | Minimum |
|---|---|
| Docker Engine | 24+ with Compose v2 |
| PostgreSQL | 16+ (included in Compose bundle) |
| AI provider key | At least one: Anthropic, OpenAI, Gemini, or Together AI |
| Memory | 512 MB (control-panel), 256 MB (MCP server) |
| Disk | 1 GB base + database growth |

Optional:

  • Clerk account for SSO/OAuth in production
  • Stripe account for usage-based billing
  • Ed25519 signing key for build attestation

Architecture

┌──────────────────────────────────────────────────────────┐
│  Docker Compose                                          │
│                                                          │
│  ┌────────────────┐   ┌─────────────────┐               │
│  │  PostgreSQL 16  │◄──│  migrate         │               │
│  │  :5432          │   │  (runs on start) │               │
│  └───────▲─────────┘   └─────────────────┘               │
│          │                                               │
│  ┌───────┴─────────┐   ┌─────────────────┐               │
│  │  control-panel   │◄──│  mcp-server      │               │
│  │  :4000           │   │  :4001           │               │
│  │  Go binary +     │   │  MCP protocol    │               │
│  │  Preact frontend │   │  endpoint        │               │
│  └──────────────────┘   └─────────────────┘               │
│                                                          │
│  Volume: pgdata (persistent)                             │
└──────────────────────────────────────────────────────────┘

Startup order: PostgreSQL starts first. The migrate container applies schema migrations automatically once Postgres is healthy. control-panel starts after migrations complete. mcp-server starts after control-panel passes its health check.

Quick Start

# Clone and configure
git clone https://github.com/pjamesiii/raptor.git && cd raptor
cp .env.example .env


Edit .env — set at minimum:


RAPTOR_ACCESS_TOKEN   (operator token for API access)


ANTHROPIC_API_KEY     (or another provider key)



Start all services

docker compose up -d

Services start on:

| Service | URL | Purpose |
|---|---|---|
| Control Panel | http://localhost:4000 | API + web interface |
| MCP Server | http://localhost:4001 | MCP protocol endpoint |
| PostgreSQL | localhost:5432 | Database (internal) |

Verify Health

After startup, confirm all services are running:

# Liveness — is the process up?
curl http://localhost:4000/api/health


Readiness — is the database connected and migrations applied?

curl http://localhost:4000/api/ready


Dependency health — per-dependency breakdown

curl http://localhost:4000/api/health/dependencies

Expected response from /api/health:

{"status": "ok"}

Expected response from /api/ready:

{"status": "ready", "database": "connected"}

Updating

git pull
docker compose build
docker compose up -d

Migrations run automatically on startup. The migrate container applies any new migrations before the control-panel starts.

Stopping and Removing

# Stop services (preserves data)
docker compose down


Stop and remove all data (destructive)

docker compose down -v

Production Checklist

Before exposing Raptor to traffic, confirm:

  • [ ] RAPTOR_ENV=production is set
  • [ ] RAPTOR_ACCESS_TOKEN is a strong, unique token
  • [ ] At least one AI provider key is configured
  • [ ] TLS terminates before Raptor (reverse proxy or load balancer)
  • [ ] Health endpoints are monitored (/api/health, /api/ready)
  • [ ] Database backups are scheduled
  • [ ] Clerk SSO or Founder Key authentication is configured
  • [ ] Secrets are stored in a secret manager, not in .env files on disk

See the Production Hardening guide for full details.
