Manage the governance policy lifecycle: validate, sign, activate, rollback, and simulate.

Policy API

The Policy API manages the governance policy lifecycle. Policies define what the AI is allowed to do, what requires confirmation, and what is denied. All policy operations are admin-only.

Policies follow a strict lifecycle: draft -> signed -> active -> superseded.

POST /api/admin/policies/validate

Validate a policy document without persisting it. Use this to check syntax and semantic correctness before signing.

Authentication: Required (Founder Key or admin)

Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| policy | object | Yes | The policy document to validate |

{
  "policy": {
    "version": "1.0",
    "mode": "enforced",
    "rules": [
      {
        "action": "chat.send",
        "effect": "allow",
        "conditions": { "trust_level": ["confirmed", "retrieved"] }
      },
      {
        "action": "action.execute",
        "effect": "require_confirmation",
        "conditions": {}
      },
      {
        "action": "data.export",
        "effect": "deny",
        "conditions": { "classification": ["confidential"] }
      }
    ]
  }
}

Response Body

{
  "ok": true,
  "valid": true,
  "warnings": [],
  "rule_count": 3
}

Validation failure:

{
  "ok": true,
  "valid": false,
  "errors": [
    {
      "path": "rules[2].conditions.classification",
      "message": "Unknown classification level: 'confidential'. Valid values: public, internal, restricted, secret."
    }
  ],
  "warnings": []
}

Error Codes

| Status | Error | When |
|--------|-------|------|
| 400 | validation_error | Malformed request body |
| 401 | unauthorized | No valid authentication |
| 403 | forbidden | Not an admin user |

POST /api/admin/policies/sign

Sign a policy document. Signing produces a cryptographic signature and stores the policy as a draft ready for activation. A policy must be signed before it can be activated.

Authentication: Required (Founder Key or admin)

Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| policy | object | Yes | The policy document to sign |

{
  "policy": {
    "version": "1.0",
    "mode": "enforced",
    "rules": [
      {
        "action": "chat.send",
        "effect": "allow",
        "conditions": {}
      },
      {
        "action": "action.execute",
        "effect": "require_confirmation",
        "conditions": {}
      }
    ]
  }
}

Response Body

{
  "ok": true,
  "policy": {
    "id": "policy_abc123",
    "version": 4,
    "status": "signed",
    "mode": "enforced",
    "rule_count": 2,
    "signature": "sha256:e5f6g7h8...",
    "signed_at": "2026-05-21T18:00:00Z",
    "signed_by": "founder"
  }
}

Error Codes

| Status | Error | When |
|--------|-------|------|
| 400 | validation_error | Policy document is invalid |
| 401 | unauthorized | No valid authentication |
| 403 | forbidden | Not an admin user |

POST /api/admin/policies/{id}/activate

Activate a signed policy. The currently active policy is superseded. Only one policy can be active at a time.

Authentication: Required (Founder Key or admin)

Path Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| id | string | Policy ID (must be in signed status) |

Request Body

No body required.

Response Body

{
  "ok": true,
  "policy": {
    "id": "policy_abc123",
    "version": 4,
    "status": "active",
    "mode": "enforced",
    "activated_at": "2026-05-21T18:05:00Z",
    "activated_by": "founder"
  },
  "superseded": {
    "id": "policy_xyz789",
    "version": 3,
    "status": "superseded",
    "superseded_at": "2026-05-21T18:05:00Z"
  }
}

Error Codes

| Status | Error | When |
|--------|-------|------|
| 401 | unauthorized | No valid authentication |
| 403 | forbidden | Not an admin user |
| 404 | not_found | Policy does not exist |
| 409 | conflict | Policy is not in signed status |

POST /api/admin/policies/rollback

Rollback to the previously active policy. The current active policy is superseded and the most recent superseded policy is re-activated.

Authentication: Required (Founder Key or admin)

Request Body

No body required.

Response Body

{
  "ok": true,
  "rolled_back_to": {
    "id": "policy_xyz789",
    "version": 3,
    "status": "active",
    "reactivated_at": "2026-05-21T18:10:00Z"
  },
  "superseded": {
    "id": "policy_abc123",
    "version": 4,
    "status": "superseded",
    "superseded_at": "2026-05-21T18:10:00Z"
  }
}

Error Codes

| Status | Error | When |
|--------|-------|------|
| 401 | unauthorized | No valid authentication |
| 403 | forbidden | Not an admin user |
| 409 | conflict | No previous policy to rollback to |

POST /api/admin/policies/simulate

Simulate a policy evaluation. Test what a given policy would allow, deny, or require confirmation for, without activating it.

Authentication: Required (Founder Key or admin)

Request Body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| policy_id | string | Yes | Policy to simulate against (any status) |
| action | string | Yes | Action to test (e.g., chat.send, action.execute) |
| context | object | No | Additional context for condition evaluation |

{
  "policy_id": "policy_draft01",
  "action": "action.execute",
  "context": {
    "trust_level": "inferred",
    "workflow": "pbc_send_notification"
  }
}

Response Body

{
  "ok": true,
  "simulation": {
    "action": "action.execute",
    "effect": "require_confirmation",
    "matched_rule": {
      "action": "action.execute",
      "effect": "require_confirmation",
      "conditions": {}
    },
    "explanation": "Action execution requires user confirmation under this policy."
  }
}

Error Codes

| Status | Error | When |
|--------|-------|------|
| 400 | validation_error | Missing required fields |
| 401 | unauthorized | No valid authentication |
| 403 | forbidden | Not an admin user |
| 404 | not_found | Policy does not exist |
