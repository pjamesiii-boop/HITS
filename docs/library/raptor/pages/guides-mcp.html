MCP Server

Connect Claude Desktop, Cursor, or any MCP client to Raptor's governed capabilities.

MCP Server Integration

Raptor includes an MCP (Model Context Protocol) server that exposes governed capabilities to AI assistants like Claude Desktop and Cursor.

Setup

1. Start the MCP server

The MCP server runs as a separate service on port 4001:

# With Docker Compose (recommended)
docker compose up -d  # starts control-panel + mcp-server + postgres


Or standalone

MCP_PORT=4001 RAPTOR_URL=http://localhost:4000 go run ./cmd/raptor-mcp

2. Configure your MCP client

Claude Desktop (~/.claude/claude_desktop_config.json):

{
  "mcpServers": {
    "raptor": {
      "url": "http://localhost:4001/mcp",
      "transport": "streamable-http"
    }
  }
}

Cursor (Settings → MCP Servers → Add):


  • URL: http://localhost:4001/mcp

  • Transport: Streamable HTTP

3. Authenticate

The MCP server supports two auth modes:

Development (token):

Authorization: Bearer your-raptor-access-token

Production (OAuth 2.1):


  1. Client discovers endpoints via GET /.well-known/oauth-authorization-server

  2. Client initiates OAuth PKCE flow

  3. Token exchange proxied through Raptor to Clerk

  4. All subsequent requests use the Bearer token

Available tools

The MCP server exposes Raptor's capabilities as MCP tools:

  • raptor_chat — send governed messages, receive structured responses with trust boundaries
  • raptor_nests — list and manage conversation nests
  • raptor_governance — query governance decisions and policy state

Available resources

  • raptor://nests — list of active nests
  • raptor://nests/{id}/summary — nest aggregate counts

What you get

Every interaction through the MCP server:


  • Goes through the same governance middleware as the REST API

  • Produces trust-bounded responses

  • Is recorded in the hash-chained audit log

  • Respects active policies and budgets

The MCP server is thin — it translates MCP protocol to Raptor API calls. All governance happens in the control panel.

OAuth discovery

curl http://localhost:4001/.well-known/oauth-authorization-server

Returns endpoints for authorization, token exchange, and JWKS (all proxied to Clerk in production).
