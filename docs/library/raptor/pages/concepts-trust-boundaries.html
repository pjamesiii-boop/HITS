Trust Boundaries

Every segment of every Raptor response carries a trust boundary — a classification that tells you how much you can rely on that specific claim.

The five boundaries

Confirmed (C)

Color: Gold | Meaning: Verified against an authoritative source.

The claim was checked against a database query, signed attestation, verified document, or audited record. The verification is recorded in the event log with source, query, and timestamp. Safe for operational decisions.

Example: "Q2 revenue was $4.2M" — verified via database query.

Executed (X)

Color: Teal | Meaning: Action ran with recorded result.

An action was actually performed — an API call made, a state transition recorded, a workflow completed. The execution is in the hash-chained event log with input, output, and timestamps.

Example: "Alert #7 acknowledged" — PBC action executed via API.

Retrieved (R)

Color: Purple | Meaning: Fetched from a system of record.

Data was pulled from a known source and presented as-is. The retrieval is recorded, but the content was not independently verified. Trustworthy to the degree the source is trustworthy.

Example: "Current alerts: 3 open" — retrieved from the alert system.

Likely (L)

Color: Slate blue | Meaning: High-confidence inference, not directly verified.

The AI's assessment based on context and reasoning. Not verified against an authoritative source. Confidence is high but the claim could be wrong. Independent verification recommended.

Example: "Renewal probability is 85-90%" — inferred from usage patterns.

Uncertain (U)

Color: Warm gray | Meaning: Limited evidence, treat with caution.

The AI is extrapolating beyond its context. Do not act without independent verification. The uncertainty is an honest signal, not a failure.

Example: "Market conditions may shift in Q4" — speculative.

Composition rules

When a response contains segments with different trust levels, the weakest boundary dominates the response-level classification. A response with one Confirmed and one Likely segment is classified as Likely overall.

Ordering (strongest to weakest): Confirmed > Executed > Retrieved > Likely > Uncertain.

Freshness lifecycle

Trust boundaries are not permanent. Each claim has a freshness state:

| State | Meaning |
|-------|---------|
| Fresh | Within the source-specific freshness window |
| Aging | Past 50% of freshness window |
| Stale | Exceeded freshness window — re-verification needed |
| Invalidated | Contradicted by newer evidence |
| Superseded | Replaced by a newer version |
