Governance Model

How Raptor governs AI — from user input through classification, policy enforcement, proposal, and commit.

Governance Model

Raptor interposes a deterministic governance layer between the user and AI execution. AI proposes. The governance core disposes. Nothing reaches the user or an external system without passing through deterministic checks.

Request lifecycle

Every user message follows the same path:

  1. Classify — the classifier receives user input and categorizes intent into one of four types:
- respond — conversational reply, no side effects - ask — clarification needed before proceeding - propose_action — AI recommends an action that requires human confirmation - execute_confirmed_action — human has confirmed, execute the action
  1. Enforce — governance middleware evaluates the classified request against:
- Capabilities — does the tenant's active policy grant this operation? - Policies — do the rules allow this specific action? - Budgets — has the tenant exceeded step, provider call, or artifact limits? - Rate limits — is the request within per-tenant API thresholds? - Suspension — is the tenant currently suspended?

If any check fails, the request is blocked and an authorization_event is recorded to the hash chain.

  1. Propose — the AI generates a response in the proposal layer. At this stage, the output is structured but uncommitted. The AI handles language, reasoning, and recommendation — it does not handle authorization or execution.
  1. Commit — the deterministic commit layer takes the proposal and:
- Assigns trust boundaries to every segment (Confirmed, Executed, Retrieved, Likely, Uncertain) - Applies the weakest-link rule for the response-level boundary - Generates decision support metadata (confidence, recommendation, basis, risk) - Hashes the payload and chains it to the previous event - Records the execution event to the immutable audit log
  1. Deliver — the committed, classified, hash-chained response reaches the user.

What makes this deterministic

The governance layer does not use AI to make governance decisions. Classification is deterministic pattern matching. Policy enforcement is rule evaluation. Trust boundary assignment follows defined rules. Hash chaining is cryptographic.

AI is used for exactly one thing: generating the content of the response. Everything around that content — authorization, classification, trust labeling, audit — is deterministic.

Governance surfaces

The governance model is visible to operators through four surfaces on every nest:

  • Actions — proposed and executed actions with confirmation state
  • Files — artifacts and documents with provenance
  • Governance — policy evaluations, authorization events, trust boundary assignments
  • Verification — hash chain integrity, claim freshness, audit export

Why this architecture

Most AI systems treat governance as a filter: run the AI, then check the output. Raptor inverts this. Governance wraps the AI — it controls what the AI is asked to do, what the AI is permitted to propose, and what happens after the AI responds.

The result: every AI output has provenance (where it came from), classification (how much to trust it), and an audit trail (what happened and when). This is not post-hoc compliance. It is the operational architecture.
