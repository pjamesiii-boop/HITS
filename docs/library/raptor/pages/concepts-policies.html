How Raptor policies control what AI can do — signed, versioned, deterministic enforcement.

Governance Policies

Policies are the rules that govern what Raptor's AI is permitted to do. They are signed with Ed25519, versioned, and applied deterministically to every governed operation.

Policy lifecycle

  1. Author — define rules (operations, actions, capabilities, budgets)
  2. Sign — cryptographically sign the policy JSON
  3. Activate — make it the active policy (previous version superseded)
  4. Evaluate — every governed request checks the active policy
  5. Supersede — when a new version activates, old versions are preserved in history

Policies are append-only. Old versions are never deleted — they're marked superseded and remain in the audit trail.

Policy structure

{
  "name": "deployment_governance",
  "version": 3,
  "mode": "enforced",
  "rules": [
    {
      "operation": "*",
      "action": "allow",
      "capabilities": ["chat:execute"],
      "max_steps": 1000,
      "max_provider_calls": 100
    },
    {
      "operation": "artifact_export",
      "action": "deny",
      "capabilities": []
    }
  ]
}

Modes

  • Enforced — policy violations block the operation (403 with reason)
  • Permissive — violations are logged but not blocked (monitoring mode)

Start with permissive to understand what your AI is doing, then switch to enforced when ready.

Built-in enforcement

Every governed request passes through:

  1. Rate limit — per-tenant API/provider limits
  2. Tenant suspension check — suspended tenants cannot execute
  3. Capability check — does the operation require a capability the policy grants?
  4. Budget check — max steps, provider calls, artifacts per operation
  5. Policy evaluation — does the active policy allow this operation?

If any check fails, the request is blocked and an authorization_event is recorded.

API endpoints

POST /api/admin/policies/validate    — validate policy JSON
POST /api/admin/policies/sign        — sign and store a policy
POST /api/admin/policies/{id}/activate — activate a signed policy
POST /api/admin/policies/rollback    — rollback to previous version
GET  /api/admin/policies             — list policy history
POST /api/admin/policies/simulate    — simulate policy against a request

UI: Policy Editor

The Settings surface includes a visual policy editor:


  • Form-based rule builder (no raw JSON editing required)

  • Templates for common patterns (budget limits, confirmation gates, operation whitelists)

  • Preview as formatted JSON

  • One-click sign and activate
