Installation

Install Raptor via Docker Compose, build from source, or sign up for cloud.

Installation

Three ways to run Raptor: Docker Compose (recommended for most teams), build from source, or cloud.

Option 1: Docker Compose (recommended)

Prerequisites

  • Docker Engine 24+ and Docker Compose v2+
  • At least one AI provider API key (Anthropic, OpenAI, Gemini, or Together AI)

Steps

Clone the repository and create your environment file:

git clone https://github.com/pjamesiii/raptor.git && cd raptor
cp .env.example .env

Edit .env and set the required variables:

# Required
RAPTOR_ACCESS_TOKEN=a-strong-random-token
ANTHROPIC_API_KEY=sk-ant-...


Optional: additional providers

OPENAI_API_KEY=sk-...
GEMINI_API_KEY=...
TOGETHER_API_KEY=...


Optional: Clerk SSO (omit for token-only auth)

CLERK_SECRET_KEY=sk_live_...
CLERK_PUBLISHABLE_KEY=pk_live_...
CLERK_DOMAIN=your-app.clerk.accounts.dev

Start the stack:

docker compose up -d

This starts three services:

| Service | Port | Description |
|---------|------|-------------|
| control-panel | 4000 | API server and workspace UI |
| mcp-server | 4001 | MCP protocol server for Claude Desktop / Cursor |
| postgres | 5432 | PostgreSQL 16 with governance event store |

Database migrations run automatically on startup via the migrate service.

Verification

Run all three health checks to confirm the stack is operational:

# Liveness — confirms the process is running
curl http://localhost:4000/api/health

{"status":"ok"}



Readiness — confirms the database connection is live

curl http://localhost:4000/api/ready

{"status":"ready"}



Dependencies — per-dependency status

curl http://localhost:4000/api/health/dependencies

{"postgres":"ok","anthropic":"ok"}

All three should return HTTP 200. If /api/ready fails, check that PostgreSQL is healthy:

docker compose ps
docker compose logs postgres

Updating

git pull && docker compose build && docker compose up -d

Migrations run automatically on restart.

Option 2: Build from source

Prerequisites

  • Go 1.25+
  • PostgreSQL 16+ (running and accessible)
  • migrate CLI (golang-migrate) for database migrations

Steps

Clone and build:

git clone https://github.com/pjamesiii/raptor.git && cd raptor
go build -o raptor-control ./cmd/control-panel

Run database migrations:

export DATABASE_URL="postgresql://raptor:password@localhost:5432/raptor?sslmode=disable"
migrate -path ./migrations -database "$DATABASE_URL" up

Set environment variables and start:

export RAPTOR_ACCESS_TOKEN=a-strong-random-token
export ANTHROPIC_API_KEY=sk-ant-...
export CONTROL_HOST=localhost
export CONTROL_PORT=4000


./raptor-control

Verification

curl http://localhost:4000/api/health
curl http://localhost:4000/api/ready
curl http://localhost:4000/api/health/dependencies

Building the MCP server

go build -o raptor-mcp ./cmd/mcp-server


export RAPTOR_URL=http://localhost:4000
export RAPTOR_ACCESS_TOKEN=a-strong-random-token
export MCP_PORT=4001



./raptor-mcp

Option 3: Cloud

  1. Go to raptor.dev and sign up with Google, GitHub, Microsoft, or email (via Clerk).
  2. Create an organization.
  3. Connect at least one AI provider in Settings.
  4. Copy your API key (starts with rpt_).

Your base URL is https://api.raptor.dev. No infrastructure to manage.

Verification

curl -H "Authorization: Bearer rpt_your_api_key" \
  https://api.raptor.dev/api/health

Health check reference

| Endpoint | Purpose | Healthy response |
|----------|---------|-----------------|
| GET /api/health | Liveness probe. Process is running. | {"status":"ok"} |
| GET /api/ready | Readiness probe. Database is connected. | {"status":"ready"} |
| GET /api/health/dependencies | Per-dependency status for all backends. | {"postgres":"ok", ...} |

Use /api/health for container orchestrator liveness probes and /api/ready for readiness gates.
