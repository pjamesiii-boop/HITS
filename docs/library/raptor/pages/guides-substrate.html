Pattern 3: Substrate

Build directly on Raptor's platform — use it as the foundation for your AI application.

When to use

  • You're building a new AI product from scratch
  • Governance, audit, and trust boundaries are core requirements
  • You want the full Raptor stack without running your own AI orchestration

Architecture

Your Users → Your Frontend → Raptor Platform
                                  ↓
                           Decision Engine
                           Governance
                           4 AI Providers
                           Hash-chain Audit
                           Trust Boundaries

Integration

1. Embed the chat interface

Use Raptor's API to build a governed chat interface in your application:

// Send governed messages
const response = await fetch('/api/chat', {
  method: 'POST',
  headers: { 'Authorization': 'Bearer rpt_...', 'Content-Type': 'application/json' },
  body: JSON.stringify({ message: userInput, conversation_id: nestId })
});


// Response includes full structured output
const { reply, trust_boundary, segments, claims, audit_trail } = await response.json();

2. Use contextual surfaces

Each nest provides structured views:

GET /api/nests/{id}/governance    — policy decisions
GET /api/nests/{id}/verification  — claim freshness
GET /api/nests/{id}/summary       — aggregate counts
GET /api/nests/{id}/actions       — action proposals
GET /api/nests/{id}/executions    — execution history
GET /api/nests/{id}/artifacts     — generated artifacts

3. Manage via API

POST /api/keys           — create API keys for your tenants
POST /api/webhooks       — receive governance events
GET  /api/billing/usage  — monitor usage
POST /api/admin/policies/sign — deploy governance policies

Multi-tenant architecture

Raptor is natively multi-tenant:


  • Row-Level Security on all tables

  • Per-tenant policies, budgets, and rate limits

  • Tenant isolation enforced at the database level

  • Each tenant gets their own nests, keys, webhooks, and billing

What you get

  • Complete AI governance platform (no orchestration code to write)
  • 4 AI providers with failover (Anthropic, OpenAI, Gemini, Together)
  • Trust boundaries on every response
  • Hash-chained audit trail
  • Policy enforcement and RBAC
  • Billing and usage metering
  • MCP server for AI assistant integration
