Nests

A nest is a governed conversation session. It is the primary object in Raptor — not a feature inside a larger container, but the unit around which everything else is organized.

Every nest holds:

  • Chat history — the full conversation between user and AI
  • Actions and proposals — proposed actions, confirmation state, execution results
  • Execution events — the hash-chained audit trail for this session
  • Artifacts — files, documents, and generated outputs
  • Governance events — policy evaluations, authorization decisions, trust assignments
  • Memory — context that persists across turns within the session

Creating a nest

A new nest starts with a clean governance state: no prior context, no inherited trust claims, fresh policy evaluation. The tenant's active governance policy applies from the first turn.

POST /api/nests
{
  "title": "Q2 deployment review",
  "metadata": { "team": "platform", "priority": "high" }
}

Nests can be created through the API or through the Control Panel interface. Every nest is tenant-scoped — it belongs to exactly one organization and is subject to that organization's RLS policies.

Nest lifecycle

Nests move through three states:

| State | Meaning |
|-------|---------|
| Active | Open for conversation, actions, and governance operations |
| Archived | Read-only. Full audit trail preserved. No new operations. |
| Forked | A new nest created from an existing one, continuing from a specific intent |

Archiving

Archived nests retain their complete hash chain, governance history, and artifacts. Archiving is a governance event recorded in the audit trail. Archived nests can be read and exported but not modified.

Forking

Forking creates a new nest that inherits context from the source nest. The fork point is recorded as a governance event in both the source and the new nest. The new nest starts its own hash chain — it references the source but does not extend it.

Use forking when a conversation branches: the original thread is complete, but a new line of inquiry continues from the same context.

Nest-level surfaces

Each nest exposes four surfaces that make governance visible to the operator:

Actions

All proposed and executed actions within the nest. Each action shows its current state (proposed, confirmed, executed, rejected), the AI's reasoning, and the execution result if applicable.

Files

Artifacts and documents attached to the nest. Each file carries provenance — who created it, when, and which execution event produced it.

Governance

The governance audit trail for this nest: policy evaluations, authorization events, trust boundary assignments, confidence assessments. This is where operators see every governance decision the system made.

Verification

Hash chain integrity for the nest. Verify that no events have been modified, inspect claim freshness across the conversation, and export the full audit trail for external review.

Why nests are the primary object

In most AI products, the conversation is a feature inside a project or a workspace. In Raptor, the nest is the workspace. Governance, provenance, and execution state are properties of the conversation, not of an external container.

This means every conversation is independently auditable, independently governed, and independently verifiable. There is no ambient state that leaks between nests. Each nest is a self-contained governance boundary.
