REST API Integration

Authenticate, send governed messages, read trust boundaries, and query audit trails via the Raptor REST API.

REST API Integration

Connect any backend or frontend to Raptor's governance substrate over HTTP. This guide walks through authentication, your first governed message, interpreting trust boundaries, and querying the audit trail.

Prerequisites

  • A running Raptor instance (cloud at https://raptor.harpyits.com or self-hosted at http://localhost:4000)
  • An API key (created via Settings UI or the /api/keys endpoint)

1. Authenticate

Raptor API keys use the rpt_ prefix. Pass them in the Authorization header or the X-Raptor-Key header:

# Option A: Bearer token
curl -H "Authorization: Bearer rpt_a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6" \
  https://raptor.harpyits.com/api/nests


Option B: X-Raptor-Key header

curl -H "X-Raptor-Key: rpt_a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6" \
  https://raptor.harpyits.com/api/nests

Include the API version header on every request:

-H "X-Raptor-API-Version: 2026-05-09"

2. Send your first governed message

curl -X POST https://raptor.harpyits.com/api/chat \
  -H "Authorization: Bearer rpt_your_key" \
  -H "Content-Type: application/json" \
  -d '{"message": "What are the risks of deploying on Friday?"}'
const res = await fetch("https://raptor.harpyits.com/api/chat", {
  method: "POST",
  headers: {
    "Authorization": "Bearer rpt_your_key",
    "Content-Type": "application/json",
    "X-Raptor-API-Version": "2026-05-09",
  },
  body: JSON.stringify({ message: "What are the risks of deploying on Friday?" }),
});
const data = await res.json();

The response includes the AI reply, trust boundary, segments, decision type, and audit trail.

3. Read trust boundaries

Every response carries a trust_boundary object that tells you how much to trust the content:

const { reply, trust_boundary, segments, decision_type } = data;


switch (trust_boundary.primary) {
  case "confirmed":   // backed by cryptographic verification
  case "executed":    // result of a completed action
    actOnResponse(reply);
    break;
  case "retrieved":   // sourced from known data
  case "inferred":    // model-generated reasoning
    showWithCaveat(reply, trust_boundary);
    break;
  case "unknown":     // insufficient basis for trust
    escalateToHuman(reply);
    break;
}

Individual segments may carry different trust levels within a single response. Always check segment-level boundaries when mixing verified facts with model reasoning.

4. Handle decision types

The decision_type field tells you what the decision engine determined:

| Decision Type | Meaning | Your action |
|---|---|---|
| respond | Informational response | Display to user |
| ask | Engine needs clarification | Prompt user for more input |
| propose_action | Action proposed, awaiting confirmation | Show proposal, ask user to confirm |
| execute_confirmed_action | Confirmed action executed | Show result with execution status |

if (data.decision_type === "propose_action") {
  const confirmed = await askUser("Proceed with this action?", data.reply);
  if (confirmed) {
    await fetch("/api/chat", {
      method: "POST",
      headers: { "Authorization": "Bearer rpt_your_key", "Content-Type": "application/json" },
      body: JSON.stringify({ message: "proceed", conversation_id: nestId }),
    });
  }
}

5. Query the audit trail

# Governance decisions for a nest
curl -H "Authorization: Bearer rpt_your_key" \
  https://raptor.harpyits.com/api/nests/{nestId}/governance


Full execution trace

curl -H "Authorization: Bearer rpt_your_key" \
  https://raptor.harpyits.com/api/executions/{id}/trace


Tenant-wide audit export

curl -H "Authorization: Bearer rpt_your_key" \
  https://raptor.harpyits.com/api/tenant/audit/export

The audit export returns four tables: authorization_events, capability_grants, governance_policies, and tenant_events.

6. Error handling

All errors follow a consistent envelope:

{
  "ok": false,
  "error": "authorization_denied",
  "message": "This operation is not permitted by the active governance policy.",
  "correlation_id": "req_abc123"
}

Handle the key error codes:

if (!res.ok) {
  const err = await res.json();
  switch (res.status) {
    case 403:
      if (err.error === "governance_denied") {
        // Policy blocked this operation — check active policy rules
      }
      break;
    case 429:
      // Rate limited — read Retry-After header
      const retryAfter = res.headers.get("Retry-After");
      break;
    case 401:
      // Key invalid, expired, or revoked
      break;
  }
}
