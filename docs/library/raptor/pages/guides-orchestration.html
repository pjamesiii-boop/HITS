Pattern 2: Orchestration

Use Raptor's decision engine as the governance layer for a multi-agent or multi-step AI workflow.

When to use

  • You're building a multi-step AI pipeline
  • You need governance decisions at each step
  • You want deterministic control flow around probabilistic agents

Architecture

Agent A → Raptor Decision → Agent B → Raptor Decision → Output
              ↓                            ↓
        Policy check                 Policy check
        Confirmation gate           Confirmation gate
        Audit event                 Audit event

Integration

1. Create a nest for the workflow

POST /api/nests
{"name": "deploy-pipeline-run-42"}

2. Use the chat API as decision points

Each step in your workflow passes through Raptor's decision engine:

// Step 1: Should we proceed with deployment?
const decision1 = await raptor.chat(nestId, {
  message: "Evaluate deployment readiness for service-X"
});
// decision1.decision_type === 'respond' | 'propose_action'


// Step 2: If action proposed, confirm
if (decision1.decision_type === 'propose_action') {
  const execution = await raptor.chat(nestId, {
    message: "proceed"
  });
  // execution.decision_type === 'execute_confirmed_action'
}

3. Each decision is governed

Every call through the decision engine:


  • Checks capabilities and budgets

  • Evaluates the active governance policy

  • Applies confidence rules (low confidence → ask, not act)

  • Records an authorization_event

  • Produces a hash-chained execution_event

Multi-provider routing

Raptor supports 4 providers (Anthropic, OpenAI, Gemini, Together AI) with automatic failover. Your orchestration layer doesn't need to handle provider failures — Raptor does it transparently.

What you get

  • Deterministic decision control flow (same policy, same enforcement every time)
  • Per-step audit trail with correlation IDs
  • Budget enforcement across the entire workflow
  • Trust boundary propagation (weakest boundary dominates)
